- **Depends on:** chunk 1 (`gr.spectrum.kappa2` sets the error scale)

- **Time:** build 30-45 min · compute about 1-2 min (peak memory about 2.5 GB at N = 1600) · your review about 1 h · plug in: no
- **Read this yourself:** `gr/fft_solver.py` (short; the reflection group and the symbol are the whole idea)

## Goal

Solve A x = b exactly (up to rounding) in O(n log n) time with FFTs, by the method of images. This is
the fastest solver in the project for the equal-skill three-player game and a reference point for
chunk 11's benchmark. It is also a test case for the main question: FFT errors are normwise (at most
about eps x kappa2 relative to max |x|), so the smallest probabilities are likely to lose relative
accuracy as N grows. At N = 800 the FFT and splu already disagree by about 1e-6 relative at the
smallest P(123). The experiment measures this; chunk 7 decides what to do about it.

The method works because the stencil is translation invariant and the triangle tiles the plane by
reflections. It does not apply to unequal skill (chunk 10), and it does not carry over to four players
(chunk 9) without new work.

## What to build (the tests import exactly this name)

`gr/fft_solver.py`
- `fft_solve(N, b) -> np.ndarray`: solves `build_A(StateSpace(N)) x = b`. b and x are float arrays of
  length n in StateSpace order; the result is a real float64 array; b is not modified. Works for every
  N >= 3 (N = 3 has a single live state).
- How it works (method of images):
  1. Lattice coordinates: the live state (x1, x2, x3) sits at grid point (x1, x2). The 6 moves are the
     neighbor offsets (1, 0), (-1, 0), (0, 1), (0, -1), (1, -1), (-1, 1), each with weight 1/6.
  2. The three sides x1 = 0, x2 = 0, x3 = 0 are mirror lines of the stencil. The reflection across
     x_a = 0 is R_a: x_a -> -x_a, and x_b -> x_b + x_a for the other two coordinates. It keeps
     x1 + x2 + x3 = N and maps the 6 moves to the 6 moves. In (x1, x2) coordinates:
     R_1(x1, x2) = (-x1, x2 + x1), R_2(x1, x2) = (x1 + x2, -x2), R_3(x1, x2) = (N - x2, N - x1).
  3. The group generated by R_1, R_2, R_3, with both coordinates taken mod P = 3N, has exactly 18
     elements: 6 linear parts times the 3 translations by (0, 0), (N, N), (2N, 2N). Each element has a
     sign, the determinant of its linear part: +1 for 9 of them, -1 for the other 9. Build the group by
     closing {identity} under the three reflections (a breadth-first search over (linear part,
     translation mod P)) and cache it per N.
  4. Odd extension: on a P x P periodic grid U, add sign(g) b(x) at g(x) for every live state x and
     every group element g. Images never land on a mirror line, so U is 0 there, and U has mean 0.
  5. Periodic solve: the symbol of A on the grid is
     sigma(alpha, beta) = 1 - (cos alpha + cos beta + cos(alpha - beta)) / 3, alpha = 2 pi k/P,
     beta = 2 pi l/P. It vanishes only at k = l = 0. So take the FFT of U, divide by sigma, set the
     (0, 0) entry to 0, transform back, and read the real part at the live states. `rfft2`/`irfft2`
     halve the work. By symmetry the periodic solution is odd, so it vanishes on the mirror lines,
     which is exactly the boundary condition of A x = b.
- The link to chunk 1: lambda_kl is sigma at the frequencies (k, l) -> (2k + l, k + 2l) on this same
  3N x 3N grid (checked to 7e-16 at N = 9).
- Assert the group size (18) and the 9/9 sign split inside the module; the tests only check answers.

## Experiment

`experiments/e06_fft.py` writes `results/e06_fft.csv`, one row per N in {50, 100, 200, 400, 800, 1600}
(`--quick`: 50, 100, 200), columns:
`N, n, P, seconds_fft, seconds_splu, speedup, fwd_err_t, kappa2, fwd_err_over_eps_kappa, resid_random,
err_vs_splu, sum_out_first_err, min_p123, p123_reldiff`.
- `seconds_fft`: median of 3 calls of `fft_solve(N, ones)` after one warm-up call. `seconds_splu`: median
  of 3 runs of `splu(A.tocsc()).solve(b)`, setup plus solve, NaN at N = 1600. `speedup` =
  seconds_splu / seconds_fft.
- `fwd_err_t` = max |x - t| / max t for b = ones, with t = 3 x1 x2 x3 / N. `kappa2` = `gr.spectrum.kappa2(N)`;
  `fwd_err_over_eps_kappa` = fwd_err_t / (eps kappa2) with eps = 2^-52.
- `resid_random` = ||b - A x||_2 / ||b||_2 for b = `np.random.default_rng(221).standard_normal(n)`;
  `err_vs_splu` = ||x - x_splu||_2 / ||x_splu||_2 for the same b (NaN at N = 1600).
- `sum_out_first_err` = max over states of |sum over i of fft_solve(N, rhs_out_first(S, i)) - 1|.
- `min_p123` = the smallest P_x(123) over live states, from splu (`gr.matrix.solve` with
  `rhs_order(S, 0, 1, 2)`; it sits at (N - 2, 1, 1)). `p123_reldiff` = |x_fft / x_splu - 1| at that
  state. Both NaN at N = 1600.
- Memory: N = 1600 peaks around 1.5-2.5 GB (a 4800 x 4800 grid); splu at N = 800 about 1 GB.

Figure: `figures/f06_fft.py` plots seconds_fft and seconds_splu against n (log-log) with an n log n
guide line, and p123_reldiff against N on a second panel.

## Acceptance tests

`pytest tests/c00_core tests/c06_fft` (20 new tests). They check agreement with splu for random b at
N = 3 to 50 (including N not divisible by 3 and a prime N), the closed form t at N = 30, 61 and 200,
small residuals at N = 100 and 101, linearity, the out-first probabilities summing to 1, an order

soft timing check (N = 400 in under 5 s).

Why p123_reldiff grows (most likely): the FFT's absolute error is spread over the whole grid, so the
smallest entries carry the largest relative error. At N = 12 and 16, against exact rationals, splu gets every entry to
about 1e-15 relative and the FFT to 5e-14 to 3e-13. At large N this column cannot say which solver is
off, only that they disagree; chunk 7 settles that.

## Red flags (bring these to the Project chat)

- Errors of 1e-3 or worse: the group is wrong (not 18 elements), a sign is wrong, or b and x are read
  in the wrong order.
- fwd_err_over_eps_kappa above 1 or growing steadily with N: precision is being lost (single-precision
  transforms, or the zero frequency not handled).
- NaN or inf anywhere: a division by sigma(0, 0) = 0.
- A timing slope near 1.5 or 2: something quadratic (a dense matrix, a Python loop over grid points, or
  a DFT by matrix multiply).
- Out of memory at N = 1600 on an 8 GB machine: drop N = 1600 from the full run and say so in
  `notes/decisions.md`; do not change the tests.
